Windows Active Directory & IT Support Lab

A virtualized Windows domain environment built to practice centralized identity administration, workstation management, support workflows, and foundational security monitoring.

Environment: VirtualBox · Windows Server domain controller (DC01) · Windows client (Client01) · Kali Linux
Focus: Active Directory · DNS/domain connectivity · Users and groups · Group Policy · File shares · Remote access · Windows event logging

Project overview

I built a small, isolated Windows enterprise-style environment to connect everyday IT support responsibilities with the identity, access, and security controls that underpin a managed Windows network. The lab provided a place to work with domain administration, endpoint configuration, troubleshooting, and security telemetry without touching production systems.

Workstreams and technical reasoning

1. Domain services and workstation enrollment

Set up a Windows domain with a domain controller and Windows client. Practiced domain membership and the dependencies between client DNS configuration, domain discovery, and authentication. A client that cannot locate the domain controller may appear to have an account problem even when the underlying issue is networking or name resolution.

2. Identity and access administration

Worked with Active Directory user and group organization, including organizational units and group-based management. This models common help desk requests such as account provisioning, access changes, and investigating sign-in failures. Group-based access helps reduce the risk of inconsistent individual permissions.

3. Group Policy and endpoint management

Explored organizational units and Group Policy to understand how workstation settings can be managed centrally. In a larger organization, consistent policies reduce configuration drift and make support and security baselines easier to maintain.

4. File sharing and remote connectivity

Practiced Windows shares and remote administration concepts including SMB and RDP. These services are useful for support but require attention to permissions, host firewalls, authentication, and network reachability.

5. Event collection and troubleshooting

Configured Windows security telemetry using Sysmon and Winlogbeat and reviewed events in an Elastic/Kibana workflow. Validated Sysmon process-creation telemetry (Event ID 1) to establish that endpoint activity was reaching the monitoring environment. This connects ordinary troubleshooting with security investigation and evidence collection.

Representative validation workflow

ipconfig /all — inspect the client's addressing, DNS servers, and domain-related network settings.

nslookup <domain-name> — verify name resolution before troubleshooting domain sign-in.

whoami /groups — review the signed-in user's group context when diagnosing access.

gpresult /r — identify applied Group Policy and troubleshoot missing settings.

Get-WinEvent -LogName Security -MaxEvents 10 — inspect recent security events as an initial log-health check.

These are representative troubleshooting commands, not a claim that every command output was preserved as project evidence.

Skills demonstrated

  • Windows domain and client administration
  • Active Directory identity, group, and OU concepts
  • DNS and network connectivity troubleshooting
  • Group Policy administration fundamentals
  • SMB/RDP support and access-control considerations
  • Sysmon, Winlogbeat, Windows event logs, and Elastic/Kibana visibility

Outcome and next improvements

The lab established a reusable environment for hands-on Windows support and security exercises. Verified telemetry included Sysmon Event ID 1. Future extensions include documented ticket scenarios, screenshots of policy results, a formal least-privilege permissions matrix, and repeatable validation checklists.
