01 / Overview

Purpose and scope

I built this lab to practice how security telemetry moves from endpoints and network sensors into a SIEM, then use that data to investigate suspicious activity. The environment supports repeatable exercises, query development, timeline building, and mapping observed behavior to MITRE ATT&CK.

Elasticsearch stores and indexes the collected events, and Kibana provides the interface for searching, filtering, and reviewing them. Logstash and Filebeat support the ingestion pipeline.

03 / Investigation workflow

From simulated activity to an evidence-based finding

Generate controlled activity

Run approved lab exercises, including Nmap scanning, against systems in the isolated environment.

Check sensor visibility

Confirm that relevant endpoint and network events arrive in Elastic and have useful timestamps and fields.

Search and correlate

Use Kibana and KQL to filter events, pivot between host and network context, and build a coherent timeline.

Document the assessment

Summarize the observed behavior, map it to ATT&CK where appropriate, and record investigation and response steps.

05 / Operations and lessons

Building a stable lab matters

During setup, Elasticsearch ran into memory pressure in the single-node environment. I worked through the resource issue and brought the lab back to a stable state so collection and investigation work could continue.

Scope: This is a learning environment with a single-node SIEM design. It is useful for hands-on telemetry and hunting practice, but it does not represent a highly available production deployment.
06 / Skills practiced

What this lab develops

What each stage proves

  • Collection proves visibility. Filebeat and Logstash move selected endpoint or network events into Elasticsearch; Kibana is where I search and compare them. A running agent alone is not enough: I check that recent events arrived with usable timestamps, host names, and fields.
  • Each sensor answers a different question. Sysmon can show endpoint process or registry activity, PowerShell logging can expose script-block content, and Zeek can add network-connection context. A single source may show an action; correlating sources helps explain where it occurred and what happened around it.
  • Controlled activity validates the pipeline. A lab scan gives me known activity to compare against collected telemetry. Seeing the expected event confirms that the data source can observe that behavior; it does not automatically prove a detection rule is accurate or production-ready.
  • Turn searches into a repeatable investigation. I record the query, the fields reviewed, the time range, the observed result, and the next pivot. That makes the finding reproducible and exposes gaps such as missing fields, delayed ingestion, or incomplete logging.
