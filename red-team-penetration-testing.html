OFFENSIVE SECURITY · CONTROLLED LAB

Red Team Penetration Testing Assessment

Network reconnaissance, WordPress enumeration, credential auditing, SSH access and post-exploitation.

Evidence standard: This case study reconstructs an earlier lab assessment of 192.168.1.110. It distinguishes documented actions from claims requiring further validation. Passwords, hashes and challenge flags are withheld.

Overview and objective

I investigated a vulnerable Linux training host to understand how exposed services, discoverable usernames and weak credentials could be chained into authenticated access. I then examined web application files and documented additional privilege-related observations.

1. Network reconnaissance

I used Nmap to enumerate network services before selecting targets for deeper investigation. The original report documents SSH and web-service assessment; an open port alone is not proof of a vulnerability.

nmap -sV -sC -A 192.168.1.110

2. Web enumeration

I inspected web pages and developer tools, used WPScan to investigate WordPress usernames and Gobuster to discover paths. The purpose was to identify relevant application and authentication surfaces.

wpscan --url http://192.168.1.110/wordpress --enumerate u
gobuster dir -u http://192.168.1.110 -w directory-list-2.3-medium.txt

3. Credential assessment

My notes record Hydra password testing against the SSH user michael and John the Ripper against a saved hash. Weak credentials were reported, but the original record does not include full cracking output or hash provenance.

hydra -l michael -P rockyou.txt ssh://192.168.1.110
john hash.txt

4. Authenticated access

The assessment documents SSH login as michael and examination of /var/www, including challenge files. Challenge flags are evidence of progress within a lab, not business data.

ssh michael@192.168.1.110
cd /var/www/
locate '*flag*'

5. WordPress and database investigation

After accessing the host, I investigated WordPress configuration and MySQL. The original presentation records a database query against wp_posts. Storing database credentials in an application configuration file is normal; the concern is whether file permissions, secret scope and database privileges were excessive.

less /var/www/html/wordpress/wp-config.php
mysql -u root -p
SELECT post_title, post_content FROM wp_posts WHERE post_title LIKE 'flag%';

Note: The original report uses an underscore in the configuration filename; the standard WordPress filename uses a hyphen. The exact path in this lab should be checked against original evidence.

6. Privilege escalation: evidence gap

The earlier report claims Python could be run with root privileges and that root-level files were accessible. However, the available command excerpt does not demonstrate the sudo invocation or include sudo -l output. I therefore present this as a reported observation rather than a fully verified exploit.

Findings and defensive recommendations

  • Weak SSH authentication: enforce strong unique passwords, MFA where supported, login throttling and authentication logging.
  • User enumeration: minimize unnecessary username disclosure and secure login endpoints.
  • Application credential exposure: restrict configuration-file access, use least-privilege database accounts and rotate exposed secrets.
  • Potential privileged Python execution: audit sudoers and eliminate unrestricted interpreter execution as root.
  • Lab flag exposure: ensure sensitive production files are not placed in public web roots.

Lessons learned

This lab taught me to connect reconnaissance to authentication testing and post-access investigation. It also reinforced the need for precise reporting: every security finding should identify the observed behavior, its impact, reproducible evidence and a defensible remediation.

Evidence limitations

The original report included screenshots of browser and terminal activity. Those screenshots are not yet embedded here. The case study avoids claiming that every attack step was independently verified and does not disclose credentials or flags.
