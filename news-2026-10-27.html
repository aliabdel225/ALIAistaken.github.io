Cover Story · Vulnerability Exploitation

PHP2Shell: When Exploit Attempts Become Working Shells

CVE-2026-109618 · CVE-2026-109619 · Updated October 27
Why it leads today's edition

Reports of successful command execution against intentionally vulnerable PHP honeypots moved this story beyond speculative scanning. CISA added both vulnerabilities to its Known Exploited Vulnerabilities catalog on October 26.

What happened?

Researchers described carefully constructed HTTP request sequences against a vulnerable Apache/PHP configuration. The sequence reportedly manipulated PHP process memory and led to command execution. In one investigation, 35 shell executions were recorded across three honeypots on October 24.

Technical significance

Successful exploitation was observed in a favorable single-worker Apache mod_php environment. This does not establish equivalent reliability across all PHP deployments. A vulnerability scanner finding, a working proof of concept and a verified production compromise are three different evidentiary claims.

Detection opportunities

Review unusual request sequences, abnormal PHP worker termination, unexpected child processes spawned by web services and outbound connections originating from web hosts. Correlate web logs, process telemetry and network activity before classifying an incident.

Defender's priority: Identify affected PHP versions, apply security updates, reduce internet exposure and preserve relevant logs for investigation. Publicly reported honeypot results do not quantify the number of compromised production servers.

Incident Response · Healthcare

Cyber Incident Disrupts New Mexico's Highest-Level Trauma Care

Incident October 26 · University of New Mexico Health System

A cybersecurity incident affected the University of New Mexico Health System, prompting ambulance diversions and canceled appointments across more than 30 clinics. Some operations began resuming later on October 26.

Why availability matters

Healthcare systems depend on clinical scheduling, patient records, communications and diagnostic workflows. Even without confirmed data theft, interruptions can have serious operational consequences.

What investigators still need to establish

The public reporting does not establish the intrusion's root cause or confirm ransomware as the cause. Claims that information was stolen should not be treated as verified until supported by evidence.

Incident-response lesson: Containment decisions in healthcare must balance forensic preservation, network isolation and continuity of critical patient services.

Network Security · Exploited CVE

VeloCloud Orchestrator: A Critical Privilege Boundary Failure

CVE-2026-114625 · Vendor security advisory

Arista's advisory describes an SQL injection vulnerability affecting on-premises VeloCloud Orchestrator deployments. The issue can allow an authenticated user with limited permissions to reach operator-level privileges. The vendor reports exploitation.

Why the blast radius matters

Network orchestrators are high-trust management systems. Their compromise can affect the configuration and security of multiple managed locations. This makes identity controls, management-plane isolation and audit logging particularly important.

Actions for defenders

Identify affected versions, install the vendor's fixed releases, restrict access to management interfaces, and review unexpected privileged actions, account changes and configuration modifications.

Offensive-security insight: The critical issue is the crossing of an authorization boundary: a lower-privileged authenticated identity reaches a function intended for a much more privileged operator.

Windows RDP starting point

Where Windows Security logs are collected in Elastic, this KQL query finds successful RemoteInteractive logons:

event.code: "4624" and winlog.event_data.LogonType: "10"

This is a starting filter, not a malicious-activity verdict. Investigate the source, account, destination, timing and follow-on actions.

Hands-On Lab · Authorized Environments Only

Investigating Suspicious Remote Access

Difficulty: Intermediate · Estimated time: 45 minutes · Tools: Windows, Elastic, Wireshark or Zeek, Nmap.

In an isolated lab, establish an authorized RDP session to a Windows target. Verify Windows Security Event ID 4624 with Logon Type 10, then perform a small, explicitly authorized port scan. Capture the traffic and correlate network events with the authentication timeline.

Write a concise report with timestamps, source and destination systems, observed ports, alternative explanations, evidence limitations and your final assessment. Relevant ATT&CK techniques include T1021.001 (Remote Desktop Protocol) and T1046 (Network Service Discovery).
